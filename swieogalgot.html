쉬엄쉬엄.

‘가까운 곳’이 아니라 ‘정말 쉬러 갈 수 있는 곳’을 찾고 싶었습니다.

낯선 동네에서 잠시 앉아 쉴 곳을 찾다가, 벤치나 공원을 검색하고 가는 길을 다시 확인해야 하는 번거로움에 주목했습니다. 주변 휴식공간을 지도와 목록으로 찾고, 선택한 장소까지 보행 경로를 확인하는 웹 서비스를 만들었습니다. 구현 과정에서는 검색 누락, 불필요한 경로 요청, 한글 입력과 모바일 화면 겹침을 개선했습니다.

01 / WHY THIS PROJECT

장소를 찾은 뒤에도
가는 길을 다시 검색해야 했습니다.

지도에는 공원·벤치·쉼터 데이터가 서로 다른 형태로 들어 있고, 어떤 장소는 정확한 앉을 자리나 입구 위치가 표시되지 않습니다. 찾기와 길안내를 각각 다른 서비스에서 해야 한다면 사용자가 다시 검색해야 합니다.

02 / PROBLEM SOLVING

만들면서 마주친 문제를
이렇게 해결했습니다.

검색부터 장소 선택, 보행 안내까지 직접 연결하면서 발견한 문제를 수정했습니다.

CASE 01 PROBLEM → CHANGE → RESULT

선택하지 않을 장소의 경로까지 미리 요청하고 있었습니다.

문제

주변 검색 후 가까운 후보 최대 12곳의 보행 경로를 미리 요청했습니다. 사용자가 한 곳만 선택해도 나머지 장소의 경로 요청이 발생하는 구조였습니다.

수정 과정과 선택

목록에서 장소를 비교하는 단계와 실제 이동 경로를 확인하는 단계를 나눴습니다. 목록은 직선거리로 정렬하고, 사용자가 장소를 선택했을 때 해당 장소의 TMAP 보행 경로를 요청하도록 바꿨습니다. 같은 출발지와 목적지의 경로는 캐시에 보관해 재사용했습니다.

결과

주변 목록을 불러올 때의 경로 사전 요청을 없앴습니다. 목록에는 직선거리임을 표시하고, 실제 도보 거리와 시간은 경로 응답을 받은 뒤 보여주도록 구분했습니다.

CASE 02 PROBLEM → CHANGE → RESULT

한글을 입력하는 중에도 검색 결과가 바뀌는 문제를 줄였습니다.

문제

한글 조합이 끝나기 전에 검색이 실행되거나, 앞서 입력한 검색어의 응답이 늦게 도착하면 현재 검색 결과와 맞지 않는 목록이 표시될 수 있었습니다.

수정 과정과 선택

한글 조합 중에는 검색을 보류하고 조합이 끝난 뒤 추천 검색을 요청하도록 처리했습니다. 응답을 받을 때는 요청 순서와 현재 검색어를 다시 확인해 이전 응답이 새 목록을 덮지 않도록 했습니다. 지역명 검색에는 현재 위치 주변 결과를 우선하도록 보완했습니다.

결과

입력 중인 검색어와 화면에 표시되는 추천 결과를 맞추고, 장소를 선택하면 해당 좌표를 기준으로 주변 휴식공간을 조회하도록 연결했습니다.

CASE 03 PROBLEM → CHANGE → RESULT

지도 서버가 응답하지 않을 때를 고려해 조회 경로를 나눴습니다.

문제

벤치와 공원은 데이터 형태가 다르고, 외부 지도 서버가 응답하지 않으면 장소가 있어도 검색 결과를 가져오지 못할 수 있었습니다. 같은 영역을 반복 검색할 때 동일한 외부 요청도 발생했습니다.

수정 과정과 선택

벤치·정자 등 점 형태 시설은 OSM 지도 조회와 Overpass 대체 조회 경로를 구성하고, 공원 후보는 TMAP 검색 결과도 결합했습니다. 같은 영역의 동시 요청은 하나로 합쳤습니다. 완료된 주변 검색은 5분 동안 같은 반경·40m 이내 위치에서 재사용하도록 했습니다.

결과

한 조회 경로의 실패에 대비하고, 최근에 검색한 가까운 영역은 재조회하지 않도록 바꿨습니다. 결과가 부족할 때는 사용자가 검색 반경을 넓힐 수 있도록 했습니다.

CASE 04 PROBLEM → CHANGE → RESULT

목록을 읽으면서 지도도 확인할 수 있도록 화면을 조정했습니다.

문제

휴대폰에서 목록을 크게 펼치면 지도가 가려지고, 작게 두면 여러 장소를 비교하기 어려웠습니다. 패널을 움직일 때 검색창이나 지도 컨트롤이 겹치는 문제도 있었습니다.

수정 과정과 선택

목록 패널을 드래그해 높이를 조절할 수 있도록 바꾸고, 기본 상태에서는 목록을 작게 보여주도록 했습니다. 패널이 올라온 위치에 맞춰 지도 컨트롤을 숨기고, 드래그 영역과 빠른 스크롤의 움직임도 조정했습니다.

결과

사용자가 지도를 볼 때와 목록을 읽을 때 필요한 영역을 직접 조절할 수 있도록 했습니다. 지도 마커와 목록에서 같은 장소 상세 화면을 열도록 선택 흐름도 통일했습니다.

03 / RESULTS & LEARNINGS

필요한 순간에 요청하고,
현재 입력과 화면에 맞춰 반영하도록 바꿨습니다.

목록 탐색과 경로 계산을 분리했습니다

주변 검색 때 최대 12개 후보에 미리 보내던 보행 경로 요청을 제거하고, 선택한 장소만 계산하도록 변경했습니다. 이는 코드에서 확인되는 요청 구조의 변화이며, 실제 검색 시간이나 API 비용 감소율을 측정한 수치는 아닙니다.

입력·검색·장소 선택이 이어지도록 개선했습니다

한글 조합 처리와 이전 응답 구분, 주변 검색 캐시, 드래그 가능한 모바일 목록을 연결했습니다. 기능을 추가하는 데서 그치지 않고 검색어를 입력하고 장소를 고르는 과정에서 생기는 요청과 화면 상태를 함께 정리했습니다.

경로 요청·주변 검색 캐시 개선 기록 ↗

지도 데이터는 휴식공간 후보 정보이며 실제 빈자리·무료 이용·개방 여부는 현장에서 확인해야 합니다.

WHAT I LEARNED

미리 많은 정보를 계산하는 것보다 사용자가 지금 필요한 정보를 적절한 시점에 요청하는 구조가 중요했습니다. 검색어가 바뀌는 순간과 목록을 움직이는 상황까지 고려하면서, API 처리와 화면 동작을 함께 개선했습니다.
