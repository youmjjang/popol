오늘의짐.

보관함을 찾는 것보다, 짐을 다시 찾으러 가는 동선이 더 문제였습니다.

여행 중 캐리어를 잠깐 맡길 때 사람들은 가장 가까운 보관함부터 찾습니다. 그런데 방문 일정을 마친 뒤 짐을 회수하러 돌아오는 길까지 계산하면 처음 선택이 오히려 불편할 수 있습니다. 이 문제에서 출발해 보관함 위치와 이동 동선을 함께 비교하고, 보관 정보는 브라우저에서 안전하게 관리하도록 기획·구현한 2인 팀 프로젝트입니다.

01 / WHY THIS PROJECT

가까운 보관함을 골라도
하루 동선은 길어질 수 있었습니다.

역별 보관함 정보가 흩어져 있고 실제 빈자리 데이터가 제공되지 않는 곳도 많습니다. 단순히 가까운 보관소만 추천하면 맡기고 찾는 과정의 전체 이동 시간이 늘어날 수 있습니다.

01출발·방문·복귀 동선 입력
02보관소 후보 조회
03전체 동선 비교
04보관 정보 암호화
02 / PROBLEM SOLVING

만들면서 마주친 문제를
이렇게 해결했습니다.

보관함을 찾고, 짐을 맡기고, 일정 후 되찾는 흐름을 기준으로 추천 조건과 정보 관리 방식을 정리했습니다.

CASE 01 PROBLEM → CHANGE → RESULT

보관하러 가는 거리보다, 되찾으러 오는 동선까지 비교했습니다.

문제

출발지에서 가까운 보관함을 골라도 일정을 마친 뒤 짐을 찾으러 되돌아와야 했습니다. 현재 위치에서 보관함까지의 거리만으로는 하루 전체 이동 부담을 비교하기 어려웠습니다.

수정 과정과 선택

출발지→보관소→방문지→보관소→최종 목적지의 네 구간으로 이동을 나눴습니다. 보관소를 이용할 때의 전체 이동과 직행 동선을 비교하고, 짐을 들고 이동하는 시간도 따로 계산해 추천에 반영했습니다.

결과

가까운 보관함을 나열하는 방식에서 전체 일정에 맞는 보관소를 비교하는 방식으로 바꿨습니다. 사용자가 우회 시간과 짐을 든 이동 시간을 보고 선택할 수 있도록 했습니다.

CASE 02 PROBLEM → CHANGE → RESULT

이동 시간만 짧아도 실제로 이용할 수 없는 조건이 있었습니다.

문제

동선이 좋아도 캐리어 규격에 맞는 칸이 없거나 회수 시각에 시설이 닫히면 이용하기 어려웠습니다. 보관함에 도착한 뒤 만차를 알게 되는 경우도 고려해야 했습니다.

수정 과정과 선택

짐 크기와 맡길 시각·회수 시각을 입력에 포함하고, 규격과 운영시간을 후보 비교에서 함께 확인하도록 했습니다. 실시간 빈자리 정보와 시설의 전체 칸수를 구분하고, 만차일 때 다른 보관소를 확인할 수 있는 흐름을 구성했습니다.

결과

추천 결과에서 동선뿐 아니라 이용 조건을 함께 확인할 수 있도록 했습니다. 전체 칸수를 현재 빈자리로 표시하지 않고, 현장 확인이 필요한 정보도 구분했습니다.

CASE 03 PROBLEM → CHANGE → RESULT

기관마다 다른 보관소 자료를 같은 형태로 정리했습니다.

문제

철도·도시철도·지자체의 자료는 역 이름, 위치, 규격, 요금과 제공 지역이 달랐습니다. 출처를 그대로 합치면 이름이 비슷한 시설을 중복 표시하거나 정보가 없는 항목까지 확인된 것처럼 보여줄 수 있었습니다.

수정 과정과 선택

운영기관과 데이터 출처를 확인해 역·시설 기준으로 정리하고, 위치·규격·운영 정보 등을 후보 비교에 사용할 수 있는 형태로 맞췄습니다. 자료가 없는 항목은 추정해서 채우기보다 제공 범위와 함께 다뤘습니다.

결과

서로 다른 출처의 보관소를 같은 입력 조건과 동선 기준으로 비교할 수 있도록 연결했습니다. 시설 정보와 실시간 이용 가능 여부를 구분해 표시했습니다.

CASE 04 PROBLEM → CHANGE → RESULT

비밀번호를 일반 메모로 남기지 않도록 저장 방식을 바꿨습니다.

문제

보관함 번호와 비밀번호를 사진이나 일반 메모에 남기면 확인은 쉽지만 정보가 그대로 노출될 수 있었습니다. 보관소 추천 이후 실제 이용 중 정보를 관리하는 과정도 필요했습니다.

수정 과정과 선택

보관 정보는 서버에 원문을 저장하는 대신 브라우저의 Web Crypto API로 암호화했습니다. 사용자 PIN에서 PBKDF2로 키를 유도하고 AES-GCM으로 암호화한 값을 로컬에 저장했습니다. 잠금 해제, 표시·복사, 회수 완료 후 기록 삭제를 구분했습니다.

결과

보관소를 고른 뒤 필요한 정보를 암호화해 보관하고, 필요할 때 확인한 뒤 보관을 종료하는 흐름을 연결했습니다. 회수 완료 시 해당 브라우저의 저장 기록을 삭제하며, 기기 전체의 흔적을 영구 제거하는 기능으로 표현하지 않았습니다.

03 / RESULTS & LEARNINGS

보관소 선택부터 회수까지
한 흐름으로 연결했습니다.

추천 기준을 하루 일정으로 넓혔습니다

출발지와 보관소 사이의 거리뿐 아니라 방문과 회수, 최종 목적지까지의 이동을 비교하도록 구성했습니다. 짐 크기와 이용 시각도 함께 입력받아 동선과 이용 조건을 한 화면에서 확인할 수 있도록 했습니다.

추천 이후의 정보 관리도 포함했습니다

보관소를 선택한 뒤 번호·비밀번호를 브라우저에서 암호화해 보관하고, 짐을 회수하면 해당 기록을 삭제하는 흐름을 연결했습니다. 개인정보를 편리하게 확인하는 과정과 저장 방식을 함께 고려했습니다.

경로의 시간은 서비스의 계산 결과이며 실제 이동 시간 절감 효과를 측정한 수치는 아닙니다. 현장 빈자리와 운영 상황은 별도로 확인해야 합니다.

WHAT I LEARNED

추천은 장소를 찾는 순간만이 아니라 이용하고 돌아오는 과정까지 고려해야 했습니다. 이동 시간만 비교하는 데서 출발해 규격·운영시간·데이터 출처·보관 정보 관리까지 연결하면서 서비스의 기준을 구체화했습니다.
