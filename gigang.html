03 / ADDITIONAL IMPROVEMENTS

만들면서 마주친 문제를
이렇게 해결했습니다.

자료 연결 근거가 약한데도 위험 등급이 올라가거나, 입력 시도가 전송 완료로 해석되거나, 변경한 차단 정책이 늦게 반영되는 문제를 개선했습니다.

CASE 01 PROBLEM → CHANGE → RESULT

WATCH 상태와 약한 연관성만으로 HIGH가 되는 흐름을 바꿨습니다.

문제

과거 판정에서는 현재 WATCH 상태나 과거 감시 이력, 파일 이름·크기 같은 근거가 HIGH 승격으로 이어질 수 있었습니다. 단순한 행동의 연결과 실제 자료 내용 일치를 구분할 필요가 있었습니다.

수정 과정과 선택

위험 등급을 일괄적으로 낮추기보다 자료 연결 근거를 나눴습니다. 팀 판정 로직에서 글자 수 유사성, 파일 이름·크기 일치, 원본 내용 일치를 구분하고 목적지 승인 여부와 민감정보 종류·건수를 함께 반영했습니다. 사건별 점수와 사용자 위험 요약도 분리했습니다.

결과

동일한 오프라인 시나리오를 두 버전에 입력한 비교에서 승인 목적지·약한 연관성 등 비교 사례의 불필요한 HIGH 분류는 4건에서 0건으로 줄었습니다. 내용 일치가 주어진 미승인 외부 입력·첨부 10건은 두 버전 모두 HIGH로 분류했습니다.

CASE 02 PROBLEM → CHANGE → RESULT

붙여넣기·첨부 시도를 전송 완료로 해석하지 않도록 했습니다.

문제

브라우저에서 붙여넣기나 첨부를 감지해도 사용자가 실제 전송 버튼을 눌렀는지, 자료가 외부에 도착했는지까지 확인되는 것은 아니었습니다. 전송 전에 막은 사건까지 유출 완료처럼 기록하면 대응 근거가 부정확해질 수 있었습니다.

수정 과정과 선택

판정 등급과 전송 상태를 구분했습니다. 사건 설명에 입력·첨부 시도, 전송 전 차단, 전송 관측을 나눠 기록하도록 보완했습니다. 전송이 관측된 경우에도 민감자료의 전송 완료까지 확인된 것으로 단정하지 않았습니다.

결과

HIGH 등급과 실제 전송 완료를 같은 의미로 사용하지 않도록 했습니다. 관제 화면에서 어떤 행동이 관측됐고 차단 결과가 무엇인지 근거를 확인할 수 있도록 사건 설명을 정리했습니다.

CASE 03 PROBLEM → CHANGE → RESULT

이미 열린 사이트의 차단 정책 반영이 늦는 문제를 개선했습니다.

문제

전면 차단 정책을 변경해도 이미 열린 탭은 다음 정책 확인까지 기다려야 했습니다. 기존 확장은 30초 알람 중심으로 갱신했고, 여러 탭을 확인할 때 순서대로 권한 응답을 기다리는 구조였습니다.

수정 과정과 선택

열린 탭에서 1초 간격으로 정책 확인을 요청하도록 보완했습니다. 여러 탭이 동시에 요청할 때는 진행 중인 정책 조회를 공유하고, 탭별 확인은 병렬로 처리하도록 바꿨습니다. 탭이 없는 상황에 대비한 기존 알람 방식도 유지했습니다.

결과

정책 확인을 30초 알람에만 의존하던 구조에서 열린 탭이 갱신을 요청하는 구조로 바꿨습니다. 1초는 확인 요청 간격이며, 실제 차단 시간은 서버·권한 응답과 브라우저의 백그라운드 실행 제한에 영향을 받습니다.
