# HTTP 반복 오류 기준 비교

2026-11-05 재집계. 입력은 기존 제출 묶음의 `03_48개_실험결과.csv`이며 original_48.csv로 원본 바이트를 보존했다. 새 로그 생성이나 탐지기 재실행은 하지 않았다. Python과 NumPy seed 7을 사용한 기존 모의실험 결과이며, 기존 보고서의 설계는 4유형 × (정상 200 + 이상 200) = 1,600개 시나리오다. 이는 1,600개의 운영 로그 행이나 실제 공격을 뜻하지 않는다.

## 계산

시간창 30/60/120초 × 횟수 3/5/8/12회 = 공통 후보 12개 각각에 대해 네 유형의 TP, FP, TN, FN을 더하고 F1을 계산했다. 합산 F1 최고인 30초·3회를 공통 비교 기준으로 선택했다. 유형별 방식은 각 유형의 F1 최고 조합을 선택한다. 동점 시 FP가 낮고 시간창이 짧은 조건을 우선한다. 실제 선택 조건은 앱의 Engine.Windows/Thresholds 값과 일치한다.

F1 = 2TP / (2TP + FP + FN). 반올림된 원본 F1의 단순 평균을 쓰지 않고 정수 건수로 다시 계산했다. 정밀도 = TP/(TP+FP), 재현율 = TP/(TP+FN), 오탐률 = FP/(FP+TN). 오탐 건수 감소율 = (117-25)/117 = 78.632...%.

| 지표 | 공통 | 유형별 |
|---|---:|---:|
| TP | 756 | 745 |
| FP | 117 | 25 |
| FN | 44 | 55 |
| TN | 683 | 775 |
| F1 | 0.9037656904 | 0.9490445860 |

오탐 92건 감소와 함께 미탐 11건 증가가 있다. 확인 시간이나 현장 생산성 증가로 환산하지 않았다. 공통 기준과 유형별 기준은 같은 기존 데이터에서 선택·평가되어 일반화 성능을 증명하지 않는다. 유형별 방식은 더 많은 조정 변수를 사용한다. 별도 홀드아웃 실험이 필요하다. 상태 코드와 반복만으로 공격 원인을 확정할 수 없다.

## 재현

```text
python http_compare.py --input original_48.csv --out recalculated
```

Python 표준 라이브러리만 사용한다. comparison.json에는 12개 공통 후보, 4개 유형별 선택 결과 및 입력 CSV SHA256이 있다. 이 스크립트는 기존 모의실험 결과의 재집계용이다. 입력 로그 생성·탐지 전체를 재현하는 스크립트가 아니다. AI 코딩 도구 지원으로 재집계·문구 정리를 수행했다.
