# GIGANG 판정 시나리오 검증 기록

실행일: 2026-11-05 (한국 시간)

대상 커밋: d7255301920c8cfb2bff1a05d46694348b6d1cfc. 이 로컬 체크아웃 기준이며 최신 원격 main 전체에 대한 검증은 아니다.

## 검증 목적과 범위

내용 일치, 승인 목적지, 글자 수 유사성, 파일 이름·크기 유사성 등 서로 다른 근거에 따라 위험 등급을 구분하는지 확인했다. 실제 CorrelationEngine.update_user_risk를 호출했고, 기존 테스트의 메모리 저장소를 사용했다. 알림 함수는 모의 처리했다.

내용 일치 여부와 민감정보 건수는 구성한 입력으로 제공했다. 따라서 이 실험은 지문 생성·내용 매칭 정확도, 실제 사용자 데이터에 대한 탐지율·오탐률, Chrome/Windows 차단 성공률을 측정한 것이 아니다. 중앙 API, 실제 DB 저장, OCR, 브라우저 네트워크 동작도 이 20건 실험의 범위 밖이다.

## 결과

| 구성한 시나리오 | 건수 | 관찰 결과 |
|---|---:|---|
| 회사 원본과 내용 일치가 주어진 미승인 외부 입력·첨부 | 10 | 10건 HIGH |
| 승인 목적지·사내 대상·약한 자료 연관성 등 비교 사례 | 10 | 10건 HIGH 미승격: NORMAL 6, WATCH 4 |
| 전체 기대 판정 일치 | 20 | 20건 일치 |
| 기존 점수·자료 검사 회귀 테스트 | 35 | 35개 통과 |
| 기존 브라우저 전송 검사 테스트 스크립트 | 2 | 2개 통과; 모의 브라우저 환경 |

20건은 독립적인 현장 표본이나 무작위 데이터셋이 아니다. 기존 정책을 기준으로 설계한 기능 검증 사례다. “탐지율 100%”, “실제 오탐률 0%”로 표현하지 않는다. 비교 사례에는 WATCH가 적절한 의심 사례도 있으므로 모두 정상 행동이라고 부르지 않는다. 회귀 테스트 수와 시나리오 수는 중복된 기능을 포함하므로 합쳐서 57개의 독립 사례라고 쓰지 않는다.

## 대표 관찰

| 조건 | 사건 점수 | 사용자 상태 |
|---|---:|---|
| 외부 입력·자료 연결 근거 없음 | 35 | NORMAL |
| 글자 수만 동일 | 44 | WATCH |
| 파일 이름·크기만 동일 | 50 | WATCH |
| 주민번호 1건 + 원본 내용 일치 + 미승인 외부 입력 | 77 | HIGH |
| 주민번호 10건 + 원본 내용 일치 + 미승인 외부 입력 | 87 | HIGH |
| 원본 내용 일치라도 승인 목적지 | 0 | NORMAL |

같은 행위라도 자료 연결 근거와 승인 여부에 따라 판정이 달라졌다. 위 점수는 초기 사용자 상태 NORMAL 기준이다. 과거 WATCH 상태나 다운로드 출처 등 다른 조건이 있으면 점수가 달라질 수 있다. 내용 일치는 민감정보 건수가 없어도 HIGH가 될 수 있었다(65점). 민감정보 유출 확정과 회사 자료의 외부 이동 시도는 구분해서 설명해야 한다.


## 재현

대상 저장소: https://github.com/dldaudlee36/GIGANG

대상 커밋을 체크아웃하고 저장소의 requirements.txt를 설치한 뒤 다음을 실행합니다.

```text
python gigang_portfolio_measure.py --repo <저장소경로> --out <결과폴더>
python -m unittest discover -s tests -p "test_*scoring.py" -v
```

두 번째 명령은 GIGANG 저장소 폴더에서 실행합니다. Python 점수·자료 검사 테스트 35개 통과를 확인했습니다. 브라우저 관련 기존 Node 테스트 2개도 모의 환경에서 통과했습니다.

개별 판정 결과는 scenario_results.csv와 scenario_results.json에서 확인할 수 있습니다. 실제 브라우저 차단 시간을 측정한 결과는 없습니다.
