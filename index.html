ISSUE 01 / API INTEGRATION

수집 경로마다 이벤트 형태가 달랐습니다.

브라우저 확장, DB 감사 로그, 로컬 에이전트에서 전달한 이벤트를 서버에서 연결해야 했습니다. 요청 데이터 형식과 수신 경로를 확인하고 일부 누락·중복 문제를 보완했습니다.

ISSUE 02 / RISK LOGIC

높은 점수 하나가 충분한 근거는 아닙니다.

규칙 기반 점수뿐 아니라 원본 자료와의 내용 일치 같은 신뢰도 높은 증거를 함께 고려했습니다. 사건별 판정 근거를 남기는 방향으로 위험도 흐름을 정리했습니다.

판정 구조 예시
25 + 10 + 30 = 65내용 일치 근거 확인 → HIGH 조건 충족 가능
74점이어도강한 근거가 없으면 점수만으로 HIGH 판정하지 않음
설명용 예시이며 실제 운영 탐지 성능 수치가 아닙니다.

참여 범위 팀원들과 이벤트 수집·DB 및 서버 연동, 위험도 판정 흐름 보완, 단말 대응 연결을 진행했습니다. 화면의 값은 시험 시점 데이터입니다.

CASE 01 / SEARCH

CASE 02 / SERVER

외부 API와 브라우저 CORS 제약

Node.js 서버에서 외부 요청을 중계하고 허용된 서버를 순서대로 시도합니다. 캐시와 동일 요청 합치기를 적용해 불필요한 호출을 줄였습니다.

CASE 03 / TRUST

직선거리는 실제 보행 경로가 아닙니다.

보행 경로 요청이 실패하면 직선거리를 경로인 것처럼 보여주지 않고 실패 상태를 명시합니다. 지도 등록 여부 역시 실제 이용 가능을 보장하지 않습니다.
