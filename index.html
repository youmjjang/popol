PROJECT 01 / RISK SCORINGEVIDENCE BEFORE LABELS
EXPLAINABLE DECISION

점수만 높다고 HIGH가 되지는 않습니다.

위험 수준을 표현할 때 ‘몇 점인가’와 ‘어떤 강한 근거가 확인됐는가’를 함께 판단하도록 설계한 점이 핵심입니다.

판정 예시 A 강한 근거 있음
기본 이벤트25
외부 목적지+ 10
내용 일치 근거+ 30
TOTAL65
HIGH 가능

내용 일치처럼 신뢰도 높은 증거가 확인되었기 때문에 HIGH 판정 조건을 충족하는 예시입니다.

판정 예시 B 강한 근거 없음
74POINTS
점수가 74점이어도
근거 조건이 없다면 점수만으로 HIGH 판정하지 않음

탐지 기준을 숫자 하나로 단순화하지 않고, 오탐 가능성과 증거의 신뢰도를 함께 고려합니다.

RULES규칙 기반 점수 계산
CONTEXT자료 연관성·민감도
EXPLAIN판정 근거 기록

* 위 점수는 발표용 판정 구조를 설명하는 예시이며, 실제 운영 환경의 탐지 성능이나 고정된 모든 규칙을 뜻하지 않습니다.

신뢰 가능한 근거가 위험 수준의 판단을 뒷받침하도록 구성했습니다.06 / 12

해결 OSM·Overpass의 착석시설/공원 후보와 TMAP 공원 검색을 결합하고, 필요 시 검색 반경을 확장했습니다.

해결 TMAP 보행 경로를 요청하고, 경로 요청 실패 시 직선거리를 보행 거리인 것처럼 대체하지 않았습니다.

→ 확인된 경로와 미확인 경로를 분리

ISSUE 01 / COVERAGE

자료 출처마다 제공 범위가 달랐습니다.

철도·도시철도 운영기관의 시설 데이터가 서로 달라 누락된 보관함을 모두 보유한 것처럼 표시할 수 없었습니다. 출처와 제공 범위를 확인하고 실제 점유 여부는 확정하지 않도록 구분했습니다.

ISSUE 02 / SECURITY

보관함 번호와 암호의 노출 가능성

보관 정보를 일반 메모에 저장하는 문제를 고려하여 브라우저 Web Crypto API 기반 암호화 흐름을 적용하고, 필요한 시점에 정보를 표시하도록 구성했습니다.
